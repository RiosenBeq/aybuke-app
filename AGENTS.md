## 1. The product

**Aybuke — "Make it glow"** An iPhone and iPad app for girls and young women (13+), also built for the Mac with Mac Catalyst: AI photo editing and image creation, plus free on-device tools.

## 3. Build, run, test

```bash
# App in the simulator (pass an explicit simulator id)
xcodebuild build -project ios/Glowlit.xcodeproj -scheme Glowlit -configuration Debug \
  -destination 'id=<simulator-udid>' -quiet

# CI-style device build without signing
xcodebuild build -project ios/Glowlit.xcodeproj -scheme Glowlit -configuration Release \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO -quiet

# Mac Catalyst build without signing (also in CI)
xcodebuild build -project ios/Glowlit.xcodeproj -scheme Glowlit -configuration Debug \
  -destination 'generic/platform=macOS,variant=Mac Catalyst' CODE_SIGNING_ALLOWED=NO -quiet

# AppCore unit tests (also run on Linux in CI)
swift test --package-path ios/Packages/AppCore

# Backend: Deno checks (CI) and SQL tests on a throwaway Postgres
(cd backend/supabase/functions && deno fmt --check && deno lint && deno check ai-image/index.ts credits-redeem/index.ts account/index.ts report/index.ts ad-reward/index.ts app-store-notifications/index.ts owner-digest/index.ts assist/index.ts polls/index.ts admin/index.ts && deno test _shared/ ad-reward/ app-store-notifications/ account/ owner-digest/ ai-image/ credits-redeem/ assist/ polls/ admin/)
backend/scripts/test-db.sh

# Generated files must stay in sync (CI checks both)
python3 scripts/build-legal.py --check
python3 scripts/export-core-strings.py --check
python3 scripts/check-honest-copy.py      # no unsupported claims, device-neutral app copy (CI)
python3 scripts/check-release-config.py   # release blockers: demo mode, legal placeholders, website URL
                                          # (CI runs it with --report; upload-app-store.sh with --online)

# Archive and upload to App Store Connect / TestFlight with an API key
# (key file in ~/.appstoreconnect/private_keys/; ids from Users and Access → Integrations)
# It stops on release blockers; GL_PREVIEW_BUILD=1 allows a deliberate preview (never submit it for review)
ASC_KEY_ID=<key id> ASC_ISSUER_ID=<issuer id> scripts/upload-app-store.sh
PLATFORM=mac ASC_KEY_ID=<key id> ASC_ISSUER_ID=<issuer id> scripts/upload-app-store.sh   # Mac App Store
```

Running the Mac app without an Apple account in Xcode: sign ad hoc (`CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO`) and point `CODE_SIGN_ENTITLEMENTS` at a scratch copy of `Config/Glowlit-macOS.entitlements` without the App Group and Sign in with Apple keys (they need a provisioning profile; never commit that). Keep the App Sandbox on: unsandboxed, SwiftData would use `~/Library/Application Support/default.store`, which other apps can share. Screenshot scenes work there too: `open <…>/Debug-maccatalyst/Aybuke.app --args -GLScreenshotScene home`.

Deterministic screens for QA and marketing (DEBUG builds): launch with `-GLScreenshotScene <scene>` (see `ScreenshotScenes.swift`; e.g. `home`, `editor`, `effects`, `share -GLShareFormat cover`, `tour`, `invite`, `video -GLEffect camcorder06` on a generated clip, `camera -GLCameraAction booth` on demo art), and `-AppleLanguages "(tr)" -AppleLocale tr` for another language; `-GLPrompt <text>` sets Create's prompt in that language. On the Mac add `-GLWindowSize 1600x1000` (UIKit points; a 1232×770 window) so every capture has the same size, and capture the window by id (`screencapture -x -o -l <CGWindowID>`). `scripts/marketing-images.py` (its header lists each scene's launch arguments) turns captures into App Store images (iPhone 1290×2796, iPad 2064×2752, Mac 2880×1800) with the captions in `docs/marketing/screenshot-captions.json` (12 languages); `--out <dir> --stand-ins` previews them before iPad and Mac captures exist.

## 4. How things work

- **AI modes** (`AppConfig.aiMode`): *backend* (production: Supabase Edge Functions → xAI `grok-imagine-image-2.0`, low quality for free and medium for Pro, 1k; Claude can't make images, so Anthropic's `claude-haiku-5-5` is only the independent safety check, on when `ANTHROPIC_API_KEY` is set), *direct* (DEBUG only, key from `ios/Config/Secrets.xcconfig`, `GL_AI_PROVIDER = xai|fal|openai|gemini`), *demo* (no backend: simulated results stamped "DEMO PREVIEW"; the banner says "Preview build", accounts and reports are hidden or say they aren't on yet, and a demo build installed from the App Store turns purchases off). Jobs are async: POST → poll → download → DELETE to confirm, which clears results server-side. Every balance the server reports on the way (the charge in the 202, a finished poll, a cancel's refund) reaches `CreditsManager` at once (an older answer never overwrites a newer one), and the server balance is read whenever a session exists, consent or not, without ever creating an account: at once after a purchase or sign-in and when the credits sheet opens, and at launch and back in the foreground at most every 15 minutes after the last read that answered (`BalanceRefreshPolicy`: every read is an Edge Function invocation, and the free plan has about 500k a month). The server holds a poll while the job runs, up to 20 s (`ai-image/long-poll.ts`, `?wait=` 0–20 for tests), so the app polls 2–3 s apart with a 45 s request timeout (`RequestFactory.pollTimeout`) and most jobs take one or two polls. The app polls through dropped connections (`PollingSchedule`: backing off, giving up after two minutes without an answer, then saying only that an undelivered result is refunded); a cancel sends `intent=cancel`, the "got it" a plain DELETE, and the server refunds any result that never reached the app (`sweep_jobs()`).
- **On-device writer** (`Services/AI/OnDeviceWriter.swift`, `app.writer`): Apple's Foundation Models (iOS 26+, Apple Intelligence, supported language) write Create's "Inspire me" ideas and "Make it magic" prompt upgrades, and can write edit ideas and captions (`ideas(_:)`). No consent or credits (nothing leaves the device); every line passes `ContentPolicy`. Since 1.1 Create's "Inspire me" and "Make it magic" ask Claude first (`CloudWriter`, see the next bullet) when `usesCloudWriter` (cloud AI allowed, consent, a session, online, no rest and no pause of all cloud AI); the on-device writer is the fallback, then `CuratedIdeas` and the offline `PromptBuilder.enhance`. Caption ideas (share composer, Auto edit) are written on the device first; Claude writes them only when she taps "More ideas from Claude", whose note says what it gets.
- **Writing help from Claude** (shown in the app as Aybik, "our AI helper"; `backend/supabase/functions/assist`, `_shared/claude-text.ts`; the app's side of the contract is `Assist.swift` in AppCore): `POST /functions/v1/assist` with `task` (`inspire`, `magic`, `captions`, `makeup`), `text` (her words, at most 400 characters, optional for `inspire`), `locale` (one of the 12 app languages) and an optional `context` (`style`, `format`, `look`) answers `{ suggestions }` (up to 4 ideas or captions of at most 120 characters, or 1–2 Create-prompt rewrites of at most 300) or, for `makeup`, `{ makeup, note }` with Makeup Studio ids only. Four more tasks (live with migration `20261104000000`; exact shapes in `backend/README.md` "Assist"): `looks` (the look finder: `{ picks: [{ kind, id, reason }] }`, 1–3 items from catalog.json's `finder`, looks, styles, effects, Enhance options and Glow looks, optional `kinds`), `poll_questions` (`{ suggestions }`, ≤ 80 characters, `context.a`/`context.b` describe the two pictures), `card_text` (`slots` → `{ slots: { storyLine|coverMasthead|coverHeadline|stripCaption: [string] } }` within each `ShareTextSlot` length) and `help` (`{ answer, support }`, ≤ 600 characters from `assist/help-facts.ts`, which must stay in step with the app; an answer in another language names screens and buttons as `assist/help-names.json` gives them, written from the string catalog by `scripts/export-help-names.py`, which `export-catalog.sh` runs and CI checks); lines that go next to her photo also skip body, face, skin, weight and rating words (`_shared/looks-words.ts`) and links, and each task counts in its own hourly bucket (`assist_kind_policy()`, migration `20261104000000`) under the shared ceilings. **The app's side of the four** (`CloudWriter.swift`'s `findLooks`, `pollQuestionIdeas`, `cardTextIdeas`, `askAybik`; AppCore `LookFinder.swift`, `AybikFallbacks.swift`): all behind `usesCloudWriter`, her words through the policy first, every answer screened again on the device (`LookFinder.usable`, `Assist.screenedQuestions`, `screenedCardLines`, `screenedAnswer`: known ids only, slot lengths, no links, no company names), a request cancelled when she types again or leaves, and a quiet fallback on any error: Explore's **Describe your vibe** (`VibeFinderCard`, `AppModel.open(_:)` routes a pick to the editor with the look, effect or Enhance option, to Create with the style, or to Retro Cam with the Glow look) falls back to `LookFinder.localMatches` over the catalog names in her language (pairs of characters for Chinese, Japanese and Korean) and then `favorites`; "Ideas from Aybik" in Ask friends sends only her typed words and the two pictures' titles (`PollDraft.hintA/B`) and keeps the presets otherwise; "Write it for me" in the share composer's text editor (`ShareTextEditor`) falls back to `CardLines`; Settings › Help › Ask Aybik (`AskAybikView`, nothing stored) falls back to the closest `HelpTopic`s (on-device answers, the cloud ones hidden under 13) and links Help & Support (`AppConfig.supportPageURL`). `AybikHelpersTests` and `TranslationTests` cover the wire formats, the screening, the matcher and every fallback line in 12 languages. DEBUG: `-GLVibeFinder "<words>"` (scene `home`), scene `askAybik` with `-GLAskAybik "<question>"`, `-GLAssistStub YES|fail|blocked` for canned answers. (Makeup ids come from catalog.json's `makeup`, exported from `MakeupStudio.swift` by `scripts/export-catalog.sh`: run it after changing looks or choices; unknown ids are dropped, a look comes with its whole recipe, extras stop at three and a lip finish needs lips). Claude Haiku 5.5 (`ANTHROPIC_ASSIST_MODEL`), text only and never a photo, thinking off at low effort, a strict JSON schema, 8 s. Her words pass the prompt policy first (422 `content_blocked` with its `category`, never a strike), and every line Claude writes passes it again before it's returned. `admit_assist()` (migrations `20261031000000`, `20261103000000`; numbers in `assist_policy()`) allows 60 requests an hour per user and per verified App Store install (the app sends `X-App-Transaction` when StoreKit has one, waiting at most 1 s, verified as for `ai-image`) and 200 per address (429 `rate_limited`); callers without a verified install share 30 an hour, and everyone together 20 a minute, 200 an hour and 1,000 a day; it refuses while AI is paused, a result safety check failed in the last 5 minutes (Claude's capacity goes to the safety checks first), or she or her install is blocked or resting. That, a ceiling, a missing Anthropic key, a Claude failure or nothing left after the checks is 503 `assist_unavailable`, and the app falls back to the on-device writer. Text help uses `ANTHROPIC_ASSIST_API_KEY` (a Claude Console workspace of its own) when it's set, else `ANTHROPIC_API_KEY`, which the safety checks always use. No credits; nothing is stored, and the logs carry counts and timings only. **Prompt polish:** before `admit_job`, `ai-image` sends a Magic Edit's or a creation's words (never the photo) to Claude once (`ai-image/polish.ts`, 6 s, the same limits and ceilings under `polish`), only for a job `admit_job()` could take (`job_admissible()`, read-only): a request it turns down is `content_blocked` like a keyword block, a strike only in the keyword policy's categories for that operation (any other category is refused before admission, uncharged); an allowed one goes on as Claude's clear English instruction (at most 600 characters) with "Only edit me" and the edit guard after it. Templates and makeup requests aren't polished, any failure keeps her words, and `PROMPT_POLISH=off` turns it off.

## 5. Rules

- **Never commit or print secrets.** AI keys live in Supabase Edge Function secrets or the git-ignored `ios/Config/Secrets.xcconfig`. Public-by-design values (Supabase anon key, RevenueCat `appl_…` key) may go in `AppConfig.json`.
- Don't commit `.claude/`. Don't add personal email addresses to public files.
- **Teen safety:** no sexual, undressing, revealing-clothing, humiliating or body/face/skin-reshaping features or prompts. The one exception is Adjust's on-device Soft skin slider, for adults (18+) only, off by default, gentle at most and texture-keeping (see "Soft skin" above); teens never see it, and no AI prompt, look or camera ever smooths skin. The prompt policy lives in `ContentPolicy.swift` (terms per category, all app languages, subject-bound so "slim gold necklace" still works); after changing it run `scripts/export-catalog.sh`, which writes `_shared/policy-terms.json` for `policy.ts`, and add cases to `_shared/policy-vectors.json` (run by both `swift test` and `deno test`). Every Magic Edit ends with `PromptBuilder.editGuard` (the server appends it too). Template prompts keep identity, skin tone and body unchanged and outfits age-appropriate.
- **Ads stay rare, optional and non-personalised:** never under 13, for Pro or on the Mac; never ATT or the IDFA; consent forms only after she asks for an ad; no new ad placements (banners, app-open ads, ads inside the editor or before a result is safe) without an owner decision and updated legal texts. Ad credits come only from the server's verified AdMob callback, never from the app.
- **Honest copy:** claims in the app, website, App Store text and legal documents must match the code (example: there is no remote template catalog, so never promise new looks without an app update). Don't name competitors in user-facing copy.
- **Names in the app:** the AI helper (Claude's writing help) is "Aybik" in every user-facing text, never "Claude", and the app names no company (Anthropic, xAI, Grok, Supabase) except where Apple requires it: the consent sheet's one small "Providers" footnote and Settings' collapsed "Providers" row (`AIProcessor.providersLine`/`providersList`, built from `AppConfig.json`), plus the legal texts. Everywhere else say "our servers", "a third-party AI provider" or "Aybik, our AI helper". Internal code, comments and docs may keep "Claude". `check-honest-copy.py` fails on "Claude" in the string catalogs, the App Store text, the screenshot captions and the legal texts, and on the company names in the catalogs and the App Store text.
- **Performance** (numbers in `docs/04-architecture.md` › Performance): render with the shared `ImageFilters.context` (or `ImageFilters.measuringContext` for unmanaged pixel measuring), never a new `CIContext`; decode photos with `ImageUtilities.decodedImage` / `ImageStore.decoded` / `ImageStore.downsampled` (ImageIO, one plain copy), never `UIImage(data:)` for pictures you process; no decoding, resizing, encoding or file I/O on the main actor; draw opaque results with `ImageUtilities.draw(…, opaque: true)` (8-bit, no alpha, so they save as JPEG; only zero-offset shadows there) and keep `UIGraphicsImageRenderer` for transparent art; keep launch work out of `GlowlitApp.init` and the first frame (`AppModel.start()` runs after it). Check a change with `-GLPerfBench <photo>` / `-GLPerfOpen <photo>` (`PerfProbe`).
- **Legal:** edit `legal/` only, then run `python3 scripts/build-legal.py`. Adding a data processor means updating the privacy policies (EN, TR, KVKK) in the same change.
- Match the surrounding code style: SwiftUI + Observation, sparse comments that explain *why*, Blush palette tokens, `Text(styled:)` for headlines with one accent word.
- Commit messages: imperative summary, short body, and the co-author trailer used in this repo's history.
